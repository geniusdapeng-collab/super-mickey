> **依赖规范**：《AI 视频生成提示词字段规范文档 v3.0》
> **更新日期**：2026-06-23

## 设计概述

在 HyperrealitySystem 的预生产链路中，PromptFusionAgent 完成字段融合后输出 25 字段的镜头提示词。由于提示词由 LLM 自动生成，存在以下风险：

| 风险类型 | 表现 | 后果 |
|:---------|:-----|:-----|
| 字段缺失 | P0/P1 必填字段为空 | 渲染失败或画面严重偏离意图 |
| 格式不合规 | 缺要素、标点错、路径不规范 | 模型无法正确解析字段语义 |
| 语义冲突 | 导演指令写"紧张"但情绪写"relaxed" | 风格碎片化，画面割裂 |
| 字符超限 | 单字段或总量超过 2500 字符 | API 截断导致信息丢失 |
| 偏离需求 | LLM 生成内容与用户 PRD 不一致 | 业务目标无法达成 |

本设计在 PromptFusionAgent 输出之后、FieldGuard 最终校验之前，新增两个环节：

- **字段内容检查环节（FieldCheckAgent）**：对 25 字段进行规则 + LLM 混合检查
- **内容修复环节（FieldRepairAgent）**：接收检查清单 + 原始 PRD，通过规则自动修 + LLM 智能修双通道完成修复

## 核心设计决策

| 决策点 | 选择 | 理由 |
|:-------|:-----|:-----|
| 检查引擎 | 规则 + LLM 混合 | 规则层覆盖 80% 确定性问题（零延迟），LLM 层处理 20% 语义一致性问题 |
| 修复策略 | 规则自动修 + LLM 智能修 | 格式/标点/路径等确定性问题用规则秒修，内容补全/一致性修正用 LLM 智能修 |
| PRD 注入 | LLM 修复 prompt 强制注入 PRD 约束 | 防止 LLM 修复后偏离业务需求 |
| 迭代机制 | 检查→修复多轮循环 | 修复可能引入新问题（如补全内容后超长），需多轮收敛 |
| 容错策略 | LLM 异常时降级不阻塞 | LLM 返回异常时跳过该步，返回原始 shot，保证管线不中断 |

## 系统位置

```
PromptFusionAgent 输出（25 字段镜头提示词）
 │
 ▼
┌─────────────────────────────────────────┐
│ 字段内容检查环节 FieldCheckAgent        │
│  · 规则引擎层 RuleChecker               │

│ 输出：CheckReport（问题清单+修改建议）   │
└──────────────────┬──────────────────────┘
 │
 ┌────────┴────────┐
 │ 原始 PRD 文档   │
 └────────┬────────┘
 ▼
┌─────────────────────────────────────────┐
│ 内容修复环节 FieldRepairAgent           │
│  · 规则自动修 RuleRepairer              │

```

## 检查规则明细

### 规则引擎检查

| 字段 | 检查规则 | 严重等级 |
|:-----|:---------|:---------|
| 导演指令 | 须含风格定位+写实要求+情绪基调三要素 | FATAL |
| 约束 | 须含画幅+分辨率+格式+帧率四参数 | FATAL |
| 灯光 | 须含主光描述+色温参数+光质定义三要素 | FATAL |
| 运镜 | 须含运动方式+速度参数+时间分布三要素 | FATAL |
| 负面约束 | 须含 `no text` 和 `no watermark` | FATAL |
| 定妆照 | 路径格式须匹配标准格式 | FATAL |
| 台词 | 句末须以 。！？… 结尾；禁止含 ；："" 等复杂标点 | FATAL/MAJOR |
| 构图 | 须含景别等级+主体位置 | MAJOR |
| 明亮约束 | 须含亮度要求+可见性+面部明亮 | MAJOR |
| 角色约束 | 须含单角色限制+禁止分身声明 | MAJOR |
| 转场 | 须指定明确转场类型 | MINOR |
| 时间轴 | 分段数 ≥ 3（正则匹配 `T\d{2}:\d{2}`） | MAJOR |
| 节奏 | 须含整体/开头/中段/高潮/结尾五段 | MINOR |
| 服装 | 须覆盖外套/内搭/下装/鞋履中至少 3 项 | MINOR |

### LLM 语义检查（6类跨字段问题）

1. 导演指令 vs 情绪/色彩：风格是否一致
2. 台词 vs 动作：疑问句台词但动作无看向对话对象的视线
3. 场景 vs 灯光：夜间户外但灯光为明亮日光
4. 正面描述 vs 负面约束：复古胶片质感但负面含 no grain
5. 角色 vs 角色一致性：外观描述与锚定词不一致
6. 时间轴 vs 运镜/动作：时间分布不匹配

## 修复策略

### 规则自动修复

| 修复项 | 触发条件 | 修复方式 |
|:-------|:---------|:---------|
| 负面词补全 | negative 缺 `no text` | 前置补充 |
| 路径规范化 | portraits 格式不匹配 | 用 PRD 角色名重建标准路径 |
| 句末标点 | dialogue 未以标点结尾 | 追加 `。` |
| 禁止标点 | dialogue 含 ；："" 等 | 替换为逗号 |
| P2/P3 截断 | P2/P3 字段超长 | 在逗号处智能截断至预算内 |

### LLM 智能修复（PRD 注入）

LLM 修复的 prompt 中强制注入 PRD 约束文本（项目名称、视频类型、风格方向、情绪基调、角色设定、特殊约束），确保修复不偏离业务需求。

## 多轮迭代机制

```
检查 → 修复 → 再检查 → 再修复 → ... → 通过或达到最大轮次
```

- 通过判定：`fatal_count == 0 and major_count == 0`
- 最大轮次：默认 2 轮
- 人工介入：达到最大轮次仍未通过，输出残留问题清单

## 接入位置

在 HyperrealitySystem 生产链路中，位于 **Layer 2 Phase 3（PromptFusionAgent）之后、FieldGuard 之前**：

```javascript
// 生产链路中的调用位置
const fusedShot = await promptFusionAgent.process(...); // Phase 3 融合
const { finalShot, reports, logs } = await fieldQualityPipeline.run(fusedShot); // 新增：检查+修复
fieldGuard.validate(finalShot); // 最终校验
```
