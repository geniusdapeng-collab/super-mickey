# 技能供给规范（Supply Spec）

> 技能库从此"只进不出"的历史结束。每个新技能必须携带出生证明、过质量闸门、接受遥测审判。

## 一、出生证明（立项门槛）

新技能立项必须满足以下任一条件，并在技能头部注明需求证据：

1. **遥测缺口**：`skill-lifecycle-report` 的墙纸镜头类型分布显示某类镜头长期凑数注入
2. **真实故事证据**：近期真实任务中出现技能库无法覆盖的题材/情绪/运镜组合
3. **赛道规划**：六大赛道批量补充计划内（见下）

**禁止**：为填满"类型×导演×情绪×运镜"笛卡尔积矩阵而生成的组合（历史教训：`喜剧_卡梅隆_孤独手持` 类可疑组合已被标记 tier=C 待重构）。

## 三、结构规范（六部分，缺一不可）

```
frontmatter（name / skill_id / dimensions / minimum_granularity）
## 技能概述（定位 / 核心功能 / 适用场景）
## 第一部分：哲学与科学基础（这个技能"为什么"有效）
## 第二部分：镜头手法（≥5 条可执行 bullet）
## 第三部分：情绪设计（配方 + 色彩/节奏/禁忌）
## 第四部分：AI提示词构建（核心原则 + 要素 + 时间轴分配 + 负向约束）
## 第五部分：禁止词清单（≥6 条，格式 "- 词：一句话理由"）
## 第六部分：实战质检清单（≥6 条 checkbox，评审环节逐条核）
```

## 四、命名规范

`类型_导演_情绪_运镜.md`，四段缺一不可：

- **类型**：须在 taxonomy 类型表内（剧情/微表情/科幻/战争/恐怖/喜剧/悬疑/惊悚/动作/孤独/纪录/奇幻）
- **导演**：须在路由器导演表内（ affinity 通道依赖），无合适导演时用流派名但放弃导演亲和
- **情绪**：须能被情绪别名表归一
- **运镜**：手持/斯坦尼康/定场/航拍 之一

## 五、质量闸门（上线前必过）

1. `node scripts/compile-skills.js` 编译无告警（qc/timeline 缺失会点名）
2. `node tests/skill-reachability-test.js` 可达性通过
3. `node tests/skill-realistic-corpus-test.js` 真实语料回归通过
4. 抽样精读：随机抽 1 个新技能逐行审读，对标 S 级样例（`微表情_压抑悲伤_无声落泪`、`剧情_卡梅隆_情感手持`）

## 六、遥测审判（上线后）

- 连续 ≥20 次运行零开火 → 自动进入 `skills-quarantine.json` 冷藏区（路由器默认排除）
- 高采纳技能升 tier，获得更大注入预算
- 每月运行 `node scripts/skill-lifecycle-report.js` 复盘
