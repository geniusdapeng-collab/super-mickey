# SuperMickey 软性优化清单（不动代码结构、不动数据结构）

> 来源：外部AI审计报告附属文档
> 日期：2026-07-25
> 前提：不改一行系统代码、不改任何 JSON schema

---

## 一、定妆照资产库（收益最大的单一杠杆）

**现状**：`characters/` 目录为空，全片走"文字定妆"。

**做法（纯资产投放，零代码）**：
1. 为高频角色类型预建定妆照库：`characters/老匠人-东方.png`、`characters/青年徒弟.png`……文件名必须含角色名或类型关键词
2. 每个故事运行前，把对应图放进 `characters/` 即可自动切换为图片定妆模式
3. 图源建议：同机位、同光位、同灰色背景、半身+手部各一张

**配套**：`data/character-registry.json` 登记常用角色锚点描述

## 二、环境变量分工调度（只改启动配置）

| 变量 | 建议值 | 收益 |
|------|--------|------|
| `STORMAXE_LLM_MODEL` | 最强模型 | 灵魂环节质量上限 |
| `STORMAXE_LLM_FAST_MODEL` | 轻量模型 | 片头优化、质检、修复提速 30-50% |
| `HYPERREALITY_LLM_MAX_CONCURRENCY` | 2~3 | 限流防超时 |
| `STORMAXE_TOTAL_DEADLINE_MS` | 3600000 | 长链路防中途死线 |
| `CREATIVE_FEEDBACK_PATH` | 持久盘路径 | 反馈数据跨重启不丢 |

## 三、创意指数反馈闭环（系统自带但一直在空转）

**现状**：`data/creative-intensity-feedback.json` 只有 6 月测试数据。

**做法**：每条视频发布 7 天后，往文件里追加真实记录：
```json
{"id":"g001_douyin","videoType":"文化遗产","intensity":0.7,"completionRate":42.5,"engagementRate":6.1,"timestamp":"2026-08-01T00:00:00.000Z"}
```

积累 20+ 条后，系统自动校准后续创作的创意指数推荐。

## 四、调用入参写满（metadata 是最好的软控制）

`system.create(intent, metadata, options)` 的 metadata 写全这 5 个字段：
```javascript
{
  title: '绳结·祇园祭前夜',
  task_id: 'G-001',
  type: '文化遗产',
  duration_sec: 60,
  target_audience: '全球社媒用户'
}
```

**original_story_text 已在链路上**——故事原文里的 `特写：xxx`、`台词：xxx` 会原样传导到提示词。

## 五、确认门的软性用法（被低估的质量阀）

1. **调整指令**：`调整:tone=克制深情` 可当场改字段不重跑
2. **确认前 grep 三秒钟**：跑红旗词检索（`未命名|未指定|占位|undefined`）
3. **reject 写病因**："标题动画是占位符，需要优化器真实生成" > "不合格"

## 六、输入侧：故事文本写作规范

**加分项格式**：
- `特写：xxx` → 进 special_notes 和视觉锚点
- `台词：xxx` → 成为钉子台词
- 具体物理动作高潮（咬绳/系扣/点火）→ action 字段受益
- 可拍时间线（前夜→黎明→当日）→ 灯光 K 值叙事自动成立

**反面**：纯情绪描写（"很感人""很震撼"）逐层衰减到空字段

## 七、回归与质量运营

1. **黄金案例库**：G-001 全套产出存档为基准，每次改 prompt 后对比
2. **LLM 代理缓存**：请求体哈希→应答缓存，回归重跑秒过已答请求
3. **出片后复盘表**：记录"字段补齐轮次"，某字段反复被打回就加固对应 Agent prompt

## 落地顺序建议

1. 定妆照库（1天）
2. 环境变量（10分钟）
3. metadata 写满（立即）
4. special_notes 风格注射（立即，每次调用时）
5. creative_style 档位校准（确认门审阅时顺手调）
6. 反馈闭环（每条片发布后 2 分钟）
7. 黄金案例回归（每次改 prompt 后）
8. 系列化启用（有系列需求时）

## 八、special_notes：系统预留的 per-call 风格注入通道

`s`pecial_notes` 是 12 标准字段之一，会沿链路进入 PRD、剧本、PromptFusion 的上下文，本质是系统自带的**免改 prompt 风格控制器**。

三种用法：
- **参考片注射**：`参考《寿司之神》手部微距特写、《小偷家族》结尾后退一步的克制` —— 模型会把具体手法翻译进灯光/运镜/剪辑字段，效果接近定向微调 prompt，但不动一行代码。
- **禁区注射**：`本片禁止配乐煽情、禁止旁白式台词` —— 对当次生成形成硬约束，不动全局禁止词表。
- **锚点注射**：把故事最关键的 2-3 个视觉锚点在此再写一遍（老年斑/旧茧/无钉木车），与 special_notes 原有的"特写提取"形成双保险，防跨环节衰减。

作用位置：创意主题 12 字段 → 需求洞察 → PRD → 剧本 → PromptFusion，全链路可见。

---

## 九、creative_style：系统内置的创意档位开关

12 字段中的 `creative_style`（0.3-0.9）不是装饰参数——它驱动 CreativeIntensityEngine 的档位推荐，直接决定剧本生成时注入的指导强度。

- 提取器自动给的值偏保守（实跑默认 0.5 且标 `unknown`），意味着大量任务在"低档位"跑完了全程。
- 软用法：创意主题确认门直接 `调整:creative_style=0.7`，剧本/摄影/灯光/调色指导即刻升到 L2 档，无需重跑。
- 档位直觉：纪实/文化遗产/情感类 0.6-0.8；口播/快销/信息类 0.3-0.4（低档位强制写实，防炫技跑偏）。

## 十、系列化机制：系统原生支持但被闲置的跨集能力

代码中已存在 `cross-episode-validator`（跨集校验）与 `episodeNumber / series.currentEpisode` 元数据通路、`data/character-registry.json` 角色注册表（当前为空）——这是一套完整的"系列片"基础设施，零代码即可启用：

- metadata 携带系列字段后，片头副标题自动生成"第N集"，跨集校验器检查角色/设定漂移。
- character-registry 登记常用角色锚点（老年斑/旧茧/作务衣用词），实现角色跨集一致。
- 组合效果：`角色注册表 + 系列元数据 + 跨集校验` = "老匠人宇宙"式系列化生产（京都绳结→川剧变脸→歙县制墨），每集独立成片、美学与角色跨集统一。

## 十一、确认门"调整"指令：系统内置的免重跑修正通道

创意主题门原生支持 `调整:字段=值` 语法，修改结果会重新渗透下游全部环节（PRD/剧本/音频都读这些字段）。它是系统级的"调色盘"，常用四条：

- `调整:type=文化遗产` —— 修正类型误判（实跑中"科普视频"曾渗入片头优化 blueprint）
- `调整:tone=沉静庄重、克制深情` —— 情绪基调渗透 PRD/剧本/音频情绪曲线
- `调整:visual_style=是枝裕和式日常纪实美学，夜灯笼暖光与晨雾自然光` —— 改视觉总纲
- `调整:dialogue_requirement=仅一句钉子台词：xxx` —— 锁死台词预算与钉子台词

**配合 creative_style**：确认门审阅 checklist 建议固定加两项——"类型与题材是否匹配"、"创意系数档位是否匹配"。
