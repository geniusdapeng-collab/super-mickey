### PromptForge 驱动方式确认

**PromptForge 子进程（`promptforge-director-worker.js`）已经是 LLM 驱动。** 使用 `llm-reasoning-engine.js` 的 `LLMEngine`，单次 LLM 调用重写全部镜头 Prompt，子进程隔离防 OOM。这是 v6.5.52 的"方案F：超简化单次调用"设计。

**但 pre-PromptForge 链路仍有大量规则驱动环节：**

| 阶段 | 驱动方式 | 说明 |
|------|----------|------|
| 剧本 → 镜头拆分 | 规则驱动（`_buildShotList`） | 硬编码拆分逻辑 |
| 角色卡片生成 | 规则驱动（模板填充） | 从 character-card.json 读取模板 |
| Opening 系统 | 混合：模板 + 少量 LLM | 模板字符串拼接 |
| Tier 架构（七层）| **LLM 驱动** | `_assembleSevenLayers` 调用 LLMEngine |
| 核心渲染（Core）| **LLM 驱动** | `buildPromptV3` 调用 LLM |
| **PromptForge 导演** | **LLM 驱动** | 单次 LLM 重写全部镜头 |
| 运镜系统 v4 | **LLM 驱动** | `generateIntraShotTimeline` 调用 LLM |
| 质量门检查 | 规则驱动 | 正则/匹配/字符数计算 |
| 标准块输出 | 规则驱动 | 字段拼接、格式化 |
| 音频增强 | 规则驱动 | L1-L4 音频层拼接 |
| 合规检查 | 规则驱动 | 字段存在性检查 |

**结论：** PromptForge 本身是 LLM 驱动的，但镜头拆分、Opening 模板、质量门等预处理环节仍是规则驱动。队长如需进一步 LLM 化，可提需求。
