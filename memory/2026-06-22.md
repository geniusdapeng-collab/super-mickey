## 预压缩追加：v2.1.4-fix9-P7~P10 最终防线

### 修复1：Director Skills 类型错误（v2.1.4-fix9-P7）
**文件**：`skills/hollywood-cinematography/cinematography-skill-router.js` 第207行
**问题**：`shot.cameraMovement` 可能为对象/数组，在 `||` 链中被选中后调用 `.toLowerCase()` 抛出 `TypeError`
**修复**：强制 `String()` 转换后再调用字符串方法：
```js
const cameraMovement = String(shot.cameraMovement || '');
const camera = (shot.cameraString || cameraMovement || '').toLowerCase();
```

### 修复2：PromptFusionAgent action 字段禁止词汇检查（v2.1.4-fix9-P8/P9）
**问题**：场景写实化后，action 字段仍含科幻词汇（全息投影、空间扭曲、时间残影、霓虹色数据流）
**根因**：`fields.action` 由 LLM 生成，不受 scene 兜底影响
**修复**：在 `_assembleStandardPrompt` 中增加 action 字段检测：
- 禁止词汇列表：`['全息', '虚拟', '投影', '空间扭曲', '时间残影', '霓虹', '数据流', '光即角色', '抽象构图', '梦境流动性', '手绘动画']`
- 检测到则替换为 5 个预定义写实动作之一（按 shotId 循环）

### 修复3：降级路径 _assembleFullPrompt 也加 action 检查（v2.1.4-fix9-P10）
**关键发现**：预算不足时走 `_fallbackSingleShot` → `_assembleFullPrompt`（降级路径），不走 `_assembleStandardPrompt`（主路径）
**后果**：主路径的 action 检查完全失效，科幻词汇通过降级路径混入最终提示词
**修复**：在 `_assembleFullPrompt` 的 `if (shot.action)` 分支前，增加同样的禁止词汇检测和替换逻辑

### 双层兜底策略总结
| 层级 | 文件 | 方法 | 检查对象 | 说明 |
|------|------|------|----------|------|
| 源头 | `scene-design-agent.js` | `_buildBatchPrompt` | scene | 预定义写实场景池，LLM 只能选不能创 |
| 最终 | `prompt-fusion-agent.js` | `_assembleStandardPrompt` | scene + action | 硬编码兜底替换，双重保险 |
| 降级 | `prompt-fusion-agent.js` | `_assembleFullPrompt` | action | 预算不足走降级路径时也要拦截 |

### 关键教训
- **预算不足 = 降级路径 = 质量失控** — 降级路径往往缺少主路径的质量校验，必须同步维护
- **双层兜底** — 源头（SceneDesignAgent）和最终（PromptFusionAgent）同时拦截，防止任何 LLM 阶段注入科幻元素
- **强制 `String()` 转换** — 任何外部数据进入字符串方法前必须类型安全，特别是 `||` 链中可能混入对象/数组
