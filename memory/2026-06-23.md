### 发现1：数据流丢失根因——index.js 的 Final-Export 覆盖

**现象**：preproduction-result.json 中 productionEngine.shots 只有5个字段（shotId, sceneType, duration, promptLength, status），所有 LLM 生成的字段（prompt, fields, negative, portraits 等）全部丢失。

**根因**：`index.js` 中有两处覆盖：
1. Line 195: `result.stages.productionEngine.shots` 第一次被赋值为精简对象
2. Line 370（Final-Export 标准化后）：`result.stages.productionEngine.shots` 再次被赋值为精简对象

这两处覆盖导致最终 JSON 中 shots 丢失了 prompt、fields、negative、portraits 等全部关键字段。

**修复方案**：
- 删除 index.js 中这两处的 shots 精简赋值
- 改为从 `productionResult.shots` 直接输出完整字段
- 保留 prompts 数组作为渲染端专用输出

### 发现2：FieldGuard CRITICAL_FIELDS 导入错误

**现象**：`字段校验失败: CRITICAL_FIELDS is not defined`
**根因**：`field-guard.js` 的 import 缺少 `CRITICAL_FIELDS`
**修复**：`const { standardizeShots, validateShots, CRITICAL_FIELDS } = require('./field-standardizer');`

### 发现3：FieldQualityPipeline 预算不足

**现象**：`[FIELD-QUALITY] ⚠️ 预算不足(剩113346ms),跳过字段质量检查`
**分析**：总预算 1200s，Phase-1+2+3 耗去约 996s，剩约 204s。FieldQualityPipeline 启动前检查剩余预算，要求至少 5 分钟（300s），实际只有 113s，故跳过。
**决策**：FieldQualityPipeline 是高质量保障环节，应保证其运行时间。方案：
- 方案A：增加总预算到 25 分钟（1500s）
- 方案B：优化 Phase-2 串行耗时（ContinuityReviewAgent 可并行或简化）
- 方案C：降低 FieldQualityPipeline 的最低预算要求

当前倾向：先执行方案C（降低最低预算到 180s），同时准备方案A（总预算提到 1500s）作为备用。

### 发现4：6个 portraits 空数组 P0 警告

**现象**：SC01-SC06 全部 `portraits: []`
**分析**：ScriptEngine 输出的角色数据含 portraits 数组，但可能在 ProductionEngine 的 `_mergeShotsByShotId` 中被覆盖。需检查 portraits 是否被加入合并字段列表。

### 发现5：FieldCheckAgent._check 方法逻辑缺陷

**代码审查发现**：`field-check-agent.js` 的 `_check` 方法内部只创建了 RuleChecker 和 LLMChecker 实例，但 **没有调用它们的 check 方法**，导致 check 总是返回空 issues 数组。

**修复**：需要在 `_check` 中显式调用：
```js
const ruleIssues = this.ruleChecker.check(shot);
const llmIssues = await this.llmChecker.check(shot);
const issues = [...ruleIssues, ...llmIssues];
```
