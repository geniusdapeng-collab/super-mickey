## 2026-06-24 00:11 - 外部专家诊断方案已落地

### 专家诊断报告
- **来源**: 外部专家分析文件 `HyperrealitySystem-字段产出问题-解决方案与风险分析.md`
- **核心结论**: 字段缺失不是"LLM 能力问题"，而是**三个代码层缺陷的叠加**:
  1. 传给 LLM 的 JSON Schema 是空的 `fields: {}` → LLM 自由发挥，只出 7-12 个字段
  2. prompt 在 FieldGuard 补齐字段之前就已经拼好了 → "假完整"现象
  3. 质量门 `targetPromptLength=1470`，但系统目标是 2500 → 门根本不知道目标值

### 4个根因（专家发现1个我们未发现的）
1. **根因1（致命）**: `schema = { shots: [{ shotId, fields: {} }] }` 空 schema 导致 LLM 不输出完整25字段
2. **根因2**: FieldGuard 后填充只标准化 shots、不重算 prompt
3. **根因3**: `maxPromptLength` 多处取值不一致（1500 vs 2500）
4. **根因4**: SIGTERM 的真正成因是 `totalDeadlineMs=30分钟` 远大于硬杀11分钟

### 10个系统级风险（P0-P3）
| 风险 | 严重度 | 问题 |
|------|--------|------|
| 质量门分母错配 | P0 | targetPromptLength=1470，1070-1500字符被判"正常" |
| maxPromptLength不一致 | P0 | 生产引擎1500、报告生成器1500、配置称2500 |
| Checkpoint固化残缺结果 | P1 | hasCheckpoint不校验字段完整性 |
| max_tokens截断整体丢字段 | P1 | 4096不够25字段×详细描述 |

| getField别名依赖完整性 | P2 | 驼峰别名没归一到snake_case |
| _truncateStandardPrompt截断 | P2 | 1500截断点在第10-12字段 |
| 并发度与内存阈值挤压 | P2 | 并发3内存杀、并发2时间杀 |
| _buildBatchPrompt中段遗忘 | P3 | 长prompt中间部分遵循度下降 |
