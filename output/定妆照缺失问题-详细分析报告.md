# 定妆照（ReferenceImages）缺失问题 - 详细技术分析报告

> 报告生成时间: 2026-06-18 17:50 CST
> 系统版本: v6.6.9.4-patch20
> 相关会话: tender-claw

---

## 问题概述

**现象**: 预生产输出的 6 个镜头（S00-S05）全部缺少定妆照引用（referenceImages），所有镜头的 `referenceImages` 字段均为空数组。

**验证数据**（从 `preproduction-result.json` 提取）:

| 镜头 | 角色 | referenceImages 数量 |
|------|------|---------------------|
| S00 | chen-zhuo | 0 |
| S01 | chen-zhuo | 0 |
| S02 | chen-zhuo | 0 |
| S03 | chen-zhuo | 0 |
| S04 | chen-zhuo, presenter | 0 |
| S05 | chen-zhuo | 0 |

**角色定妆照实际存在**: `_legacy.characters['chen-zhuo'].portraits` 包含 4 个角度的完整路径：
- `front`: `characters/chen-zhuo/portraits/chen-zhuo-cg-v3-front.png`
- `threeQuarter`: `characters/chen-zhuo/portraits/chen-zhuo-cg-v3-threeQuarter.png`
- `closeup`: `characters/chen-zhuo/portraits/chen-zhuo-cg-v3-closeup.png`
- `side`: `characters/chen-zhuo/portraits/chen-zhuo-cg-v3-side.png`

**结论**: 定妆照文件存在且路径正确，但 Stage-11 渲染输出时 referenceImages 未被正确填充。

---

## 根因分析

### 根因一：S01-S05 内容镜头 — FinalPromptBuilderV3 新链路硬编码 `referenceImages: []`

**代码位置**: `zhuoyue-system/core/nirath-master-pipeline.js` line ~5692-5797

**问题描述**:

Stage-11 渲染流程中，所有镜头先走旧链路生成 Prompt，然后调用 `FinalPromptBuilderV3.build()`（新链路）。新链路成功后，`gotoFinalSubmit = true`，进入新链路成功分支：

```javascript
if (gotoFinalSubmit && newChainResult) {
  // ...
  const standardOutput = {
    shotId: shot.id,
    id: shot.id,
    type: shot.type || 'generic',
    scene: shot.scene || '',
    prompt,
    referenceImages: [],  // ← ⚠️ 硬编码空数组！定妆照数据丢失
    duration: shot.duration,
    length: prompt.length,
    // ...其他字段
  };
  prompts.push(standardOutput);
  
  // v6.6.9: 新链路成功，跳过后续增强处理
  continue;  // ← ⚠️ 跳过了 line 6226+ 的 referenceImages 处理代码
}
```

**关键问题**:
1. `referenceImages: []` 是硬编码的空数组，没有从 `stages.characters` 中读取定妆照数据
2. `continue;` 语句跳过了主渲染路径中 line 6226+ 的 referenceImages 构建逻辑
3. 所有走新链路的镜头（S01-S05）都会丢失定妆照

**主渲染路径中被跳过的 referenceImages 构建代码** (line 6226-6241):

```javascript
let referenceImages = [];
const charIdMap = { 'taotie': 'tao-tie', 'tao-tie': 'tao-tie' };
for (const rawCharId of (shot.characters || [])) {
  const charId = charIdMap[rawCharId] || rawCharId;
  const char = stages.characters?.[charId];
  if (!char) continue;
  referenceImages = mergeReferenceImages(
    referenceImages,
    normalizePortraitMapToReferenceImages(charId, char.portraits || char.profile?.generatedAssets?.portraits)
  );
}
shot.referenceImages = referenceImages;
```

这段代码是正确的，但由于 `continue;` 被跳过了。

### 根因二：S00 片头镜头 — `opening-system-v3.js` 未返回 `referenceImages`

**代码位置**: 
- `zhuoyue-system/systems/opening-system-v3.js` 返回对象缺少 `referenceImages` 字段
- `zhuoyue-system/core/nirath-master-pipeline.js` line 4219

**问题描述**:

`opening-system-v3.js` 的 `generateGenericOpening` 函数返回：

```javascript
return {
  duration,
  acts: { act1, act2, act3 },
  prompt: fullPrompt,
  promptLength: fullPrompt.length,
  characters: { protagonist: presenter, beast: null },
  portraits,      // ← 这是 config.portraits（输入的 portraits 对象）
  portraitPaths,  // ← 这是提取的路径数组（但提取逻辑有 bug，见下方）
  // ❌ 缺少 referenceImages 字段！
};
```

在 `nirath-master-pipeline.js` line 4219：
```javascript
referenceImages: openingResult.referenceImages || [],  // ← openingResult.referenceImages 不存在，结果为 []
```

**额外问题**：`opening-system-v3.js` 中 `portraitPaths` 的提取逻辑有数据格式不匹配问题：

```javascript
const presenterPortraits = portraits[presenterId] || portraits[presenterName] || [];
// portraits[presenterId] 是一个对象 {front: ..., threeQuarter: ...}
// 但代码按数组处理：presenterPortraits.length
// 对象的 length 属性是 undefined，条件 presenterPortraits.length > 0 为 false
if (presenterPortraits && presenterPortraits.length > 0) {
    portraitPaths = presenterPortraits.slice(0, 4);  // ← 永远不会执行
    portraitRef = ' @image1';
}
```

这导致片头 Prompt 中缺少 `@image1` 角色引用标记。

---

### 根因三：`_releaseMemory` 释放 `result.stages.characters` 导致后续阶段无法访问角色数据

**代码位置**: `zhuoyue-system/core/nirath-master-pipeline.js` line 2294-2313

**问题描述**:

Stage-11 之后，`_releaseMemory` 被调用：

```javascript
// v6.6.5-fix: 主进程内存释放(OOM修复)
this._releaseMemory?.(result);

_releaseMemory(result) {
  // ...
  if (result.stages.characters) result.stages.characters = null;  // ← 角色数据被清空
  // ...
}
```

虽然 Stage-11 内部执行时 `stages.characters` 还有数据，但：
1. Stage-13 PromptForge 如果需要访问角色数据，会得到 null
2. 任何 Stage-11 之后的阶段都无法访问定妆照信息
3. 这个设计假设 Stage-11 之后不再需要角色数据，但实际可能需要

## 修复方案建议

### 方案一：修复 `gotoFinalSubmit` 分支中的 referenceImages（推荐）

在 `nirath-master-pipeline.js` line ~5720 处，将硬编码的 `referenceImages: []` 改为从 stages.characters 动态构建：

```javascript
// 构建 referenceImages（复用主渲染路径的逻辑）
let referenceImages = [];
const charIdMap = { 'taotie': 'tao-tie', 'tao-tie': 'tao-tie' };
for (const rawCharId of (shot.characters || [])) {
  const charId = charIdMap[rawCharId] || rawCharId;
  const char = stages.characters?.[charId];
  if (!char) continue;
  referenceImages = mergeReferenceImages(
    referenceImages,
    normalizePortraitMapToReferenceImages(charId, char.portraits || char.profile?.generatedAssets?.portraits)
  );
}

const standardOutput = {
  // ...
  referenceImages,  // ← 使用动态构建的 referenceImages
  // ...
};
```

### 方案二：修复 `opening-system-v3.js` 返回 referenceImages

1. 在 `generateGenericOpening` 返回对象中添加 `referenceImages` 字段
2. 修复 `portraitPaths` 的数据格式处理逻辑（对象 vs 数组）
3. 确保片头 Prompt 中注入 `@image1` 角色引用标记

### 方案三：在主渲染路径中统一构建 referenceImages（而非在分支中分别处理）

将 referenceImages 构建逻辑从 `if/else` 分支中提取出来，统一在循环末尾执行：

```javascript
// 统一构建 referenceImages（无论走新链路还是旧链路）
let referenceImages = [];
// ...构建逻辑...

if (gotoFinalSubmit) {
  // 新链路分支
  const standardOutput = { ..., referenceImages };
} else {
  // 旧链路分支
  const standardOutput = { ..., referenceImages };
}
```

### 方案四：延迟释放 characters 数据

将 `_releaseMemory` 中对 `characters` 的释放延迟到 Stage-16（最终输出）之后：

```javascript
_releaseMemory(result) {
  // ...释放其他大对象...
  // ❌ 不要在这里释放 characters
  // if (result.stages.characters) result.stages.characters = null;
}
```
