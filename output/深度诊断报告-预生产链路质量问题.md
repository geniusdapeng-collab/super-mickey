# 超现实系统预生产质量深度诊断报告

> 任务: 陈卓健康科普系列 · 第一集
> 系统版本: v2.1.4-fix7
> 诊断时间: 2026-06-22
> 诊断人: 小G

---

## 一、结论先行

**当前预生产链路存在系统性信息漏斗问题**。

LLM 模块本身在运行（Token 消耗正常），但输入给 LLM 的上下文被严重截断和过滤，导致：
1. 角色核心描述丢失（"穿警服" → 变"运动外套"）
2. 场景主题跑偏（医疗科普 → 变户外跑道）
3. 片头标题缺失（明确需求 → 未生成）
4. 个别镜头空心化（SC05 仅 214 字符）

**根因不是 LLM 能力问题，是"提示词工程链路"设计缺陷**——每个 Agent 的输入上下文被过度精简，丢失了导演决策所需的完整信息。

---

## 二、问题逐层拆解

### 🔴 P0: 角色描述完全丢失（影响所有镜头）

**现象**: 陈卓从"穿警服的科普讲解员"变成"深灰色运动外套晨跑者"

**根因定位**:

```
用户 intent ──→ ScriptGenerator ──→ Adapter ──→ ProductionEngine ──→ SceneDesignAgent
     │              │                    │                  │
     │         正确提取            【description 字段丢失】      │
     │         "穿警服的陈卓"            未传入下游              │
     │                                                          │
     └────────────────────────────────────────────────────────→ LLM 完全看不到"警服"
```

**代码证据**:

1. **Adapter.js `_adaptCharacters`** (第 210-228 行):
```javascript
const adapted = {
  character_id: char.character_id,
  name: char.name,
  role: char.role,
  visual_anchor: {
    core_features: char.visual_anchor?.core_features || [],  // ← 只传了 core_features
    reference_images: char.visual_anchor?.reference_images || []
  },
  portraits: this._resolvePortraitPaths(...)  // ← 只传了定妆照路径
};
// ❌ 没有 description 字段！
```

2. **ScriptGenerator.js** (第 441 行):
```javascript
core_features: c.description ? c.description.split(/[,，、]/).filter(s => s.trim()) : ['写实人物']
```
虽然 ScriptGenerator 把 description 拆成了 core_features，但 Adapter 的 `_adaptCharacters` 根本没读取 `visual_anchor.core_features` 来重建 description。

3. **SceneDesignAgent._buildPrompt**:
```javascript
const characterDesc = characters.map(c =>
  `- ${c.name}: ${c.description || '无描述'}${c.portraitPaths ? ' [有定妆照]' : ''}`
).join('\n');
```
`c.description` 是 `undefined`，所以 LLM 看到的是：`陈卓: 无描述 [有定妆照]`

4. **PromptFusionAgent._buildBatchPrompt**:
```javascript
const characterInfo = characters.map(c => `- ${c.name}: ${c.description || ''}`).join('\n');
```
同样是 `undefined`，LLM 看不到任何角色描述。

**结果**: LLM 只能根据角色名"陈卓" + 定妆照来推断。定妆照是正面照，看不出服装细节，LLM 默认生成"运动装"（因为主题涉及健身/横纹肌溶解）。

---

### 🔴 P0: 场景主题跑偏（医疗科普 → 户外跑道）

**现象**: 6 个镜头全部在"塑胶跑道/林荫道/晨雾"，没有任何医疗/实验室/诊室场景

**根因定位**:

PromptFusionAgent 的输入提示词极度贫乏：

```javascript
// PromptFusionAgent._buildBatchPrompt 实际传给 LLM 的内容：
画幅:16:9
角色:陈卓:        ← 无描述
镜头:
SC01(8s): 清晨6:30的城市社区户外塑胶跑道... | 警觉肃杀 | 健身后尿液变成... | 运镜:固定机位中景... | 灯光:...
```

**关键缺失**:
- ❌ 没有视频标题
- ❌ 没有"横纹肌溶解"主题说明
- ❌ 没有"健康科普"类型标注
- ❌ 没有"医学检查/实验室"场景需求
- ❌ 没有"第一集：症状及实验室检查"的内容定位

LLM 只能看到"健身后尿液变色"这句台词，自然推断场景是"户外健身跑道"。这是**上下文缺失导致的级联错误**。

---

### 🔴 P0: 片头标题缺失（明确需求未满足）

**现象**: 用户明确要求"第一集有片头镜头，开头需要主标题和副标题"，但 FieldGuard 报错：`Opening shot missing: title | Opening shot missing: subtitle`

**根因定位**:

1. **OpeningDesignAgent 确实运行了**（日志："OpeningDesignAgent 完成 ✓"，耗时 12.4s）
2. **但注入逻辑有问题**。ProductionEngine 第 462-470 行：
```javascript
const openingShot = currentShots.find(s => s.sceneType === 'opening');
if (openingShot) {
  openingShot.title = od.title || titleOverlay.mainTitle || titleOverlay.main_title || '';
  // ...
}
```
问题在于：
- `currentShots` 中是否有 `sceneType === 'opening'` 的镜头？
- 如果剧本引擎没生成 opening 类型场景，这个注入就找不到目标
- 即使有，注入后 FieldGuard 检查的是 `title` 和 `subtitle` 字段，但代码中注入的是 `title`，可能字段名不匹配

**更深层问题**: 剧本引擎的 `isSeriesNonFirst` 逻辑可能错误地将 opening 降级了，或者根本没生成 opening 场景。

---

### 🟡 P1: SC05 空心化（214 字符）

**现象**: SC05 只有约束层+基础层，没有场景/角色/动作

**根因**: PromptFusionAgent 的 LLM 返回了空的 `fields` 对象，或者 `_assembleStandardPrompt` 时所有字段都为空。

可能原因：
1. LLM 对该镜头的生成失败了（但并发模式下没有正确降级）
2. 该镜头的输入信息极度缺失，LLM 无法生成有效内容
3. `_fuseSingleShot` 返回了 `fields: {}`，`_assembleStandardPrompt` 只拼接了 constraint + baseline

---

### 🟡 P1: 时间轴字段丢失

**现象**: 审核报告显示"有时间轴: ✗"，但提示词中实际有 `【时间轴】T00:00-T00:08`

**根因**: 审核报告的检查逻辑可能有问题，但这不是核心质量问题。

## 三、系统性根因总结

### 3.1 信息漏斗模型

```
用户输入（丰富上下文）
    ↓
[ScriptEngine] 剧本生成 ✅ 保留完整上下文
    ↓
[Adapter] 适配转换 ❌ 丢失 60%+ 关键信息
    - description 字段丢失
    - 场景完整描述截断
    - 系列/主题信息未传递
    ↓
[ProductionEngine Agents] LLM 处理 ❌ 输入极度贫乏
    - SceneDesignAgent: 只能看到角色名+50字场景梗概
    - PromptFusionAgent: 只能看到截断后的镜头信息
    - OpeningDesignAgent: 只能看到标题，看不到内容定位
    ↓
[FieldGuard] 字段校验 ⚠️ 发现缺失但无法修复
    - 标题缺失报错
    - 但无法反向推动上游修正
```

### 3.2 各 Agent 上下文缺失对照表

| Agent | 需要什么 | 实际得到 | 缺失率 |
|-------|---------|---------|--------|
| SceneDesign | 完整角色设定、场景主题、情绪目标 | 角色名+无描述、50字场景梗概 | ~70% |
| VisualLanguage | 完整场景描述、角色动作、运镜需求 | 截断后的 scene/action/mood | ~50% |
| PromptFusion | 完整导演意图、所有字段内容 | 角色名（无描述）、50字台词、30字运镜 | ~80% |
| OpeningDesign | 系列定位、主题风格、内容摘要 | 仅标题文字 | ~90% |

### 3.3 核心设计缺陷

**缺陷 1: Adapter 是信息黑洞**
- `_adaptCharacters` 不传递 `description`
- `_adaptScenes` 把完整场景描述压缩成 50 字的 `prompt_base`
- 用户 intent 的丰富信息（风格、要求、注意事项）完全丢失

**缺陷 2: Agent Prompt 设计过于精简**
- 以为"少即是多"，结果是"少到无法决策"
- PromptFusionAgent 的 batch prompt 只有 200-400 字上下文，LLM 无法做高质量融合
- 没有传递"这是医疗科普视频"这一最关键的类型信息

**缺陷 3: 缺乏跨层上下文传递机制**
- Layer 0（需求清单）确认了"创意指数 0.82""全写实""警服"
- 但这些信息没有向下传递到 Layer 2（制作引擎）
- 每个 Agent 都是"盲人摸象"

## 四、修复方案

### 方案 A: 最小修复（快速可用）

**目标**: 不改动架构，只修复关键信息传递

1. **Adapter 补全 description**
```javascript
// _adaptCharacters 中添加：
description: char.description || char.visual_anchor?.persona || '',
```

2. **PromptFusionAgent 增加完整上下文**
```javascript
// _buildBatchPrompt 中增加：
const videoContext = `视频主题：${blueprint.title}\n内容定位：${blueprint.metadata?.content_summary || ''}\n风格要求：${blueprint.config?.style || '写实'}\n角色设定：${characterInfo}`;
```

3. **强制角色服装注入**
```javascript
// 在最终 prompt 组装时，从 metadata 提取角色服装并强制写入
```

### 方案 B: 架构级修复（推荐）

**目标**: 建立"导演指令上下文"传递机制

1. **新增 DirectorContext 对象**
   - 从 Layer 0 确认后生成，包含：主题、风格、角色、场景要求、禁止项
   - 每个 Agent 都能读取 DirectorContext
   - Agent prompt 自动拼接 DirectorContext

2. **重构 Agent Prompt 模板**
   - 每个 Agent 的 prompt 分为：固定指令 + DirectorContext + 镜头具体信息
   - 不再截断关键信息

3. **Adapter 保留完整信息**
   - 所有原始字段原样传递
   - 只在需要时做格式转换，不做信息丢弃

### 方案 C: 即时 workaround（本次任务）

在当前任务中，可以：
1. 手动编辑生成的提示词，把"运动外套"改为"警服"
2. 手动添加片头标题 overlay
3. 重新跑 SC05 的 prompt fusion

## 六、结论

**当前系统不是"LLM 没发生作用"，而是"LLM 在瞎猜"**。

每个 LLM Agent 都在运行，消耗 Token，生成内容，但因为输入上下文被过度精简，LLM 被迫基于极其有限的信息做推断，导致：
- 推断角色服装 → 运动装（因为主题是健身相关）
- 推断场景 → 户外跑道（因为台词提到健身）
- 推断风格 → 晨雾+运动（因为看不到"科普""警服""诊室"等关键指令）

**修复优先级**:
1. 🔴 **P0**: Adapter 补全 description 字段传递
2. 🔴 **P0**: PromptFusionAgent 增加完整导演上下文
3. 🟡 **P1**: 建立 DirectorContext 跨层传递机制
4. 🟡 **P1**: 修复片头标题注入逻辑
