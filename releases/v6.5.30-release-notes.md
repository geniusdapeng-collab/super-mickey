## 修改文件详情

### 1. `systems/nirath-master-pipeline.js`（4处修改）

- **`inferCharactersFromScene`**: 重构角色推断逻辑
  - generic 模式：推断 chen-nurse, coach-li, xiaoG（基于场景类型）
  - Nirath 模式：推断 xiaoG, jiu-wei-hu, tao-tie（原逻辑）
  - 新增 `worldSetting` 参数支持

- **`enrichVisualPromptWithFiveElements`**: 添加 mode 守卫
  - `if (this.mode !== 'nirath') return visualPrompt;`
  - 阻止 Nirath 五要素（主动性、信任、告别等）注入 generic 模式

- **`stageStoryboard`**: 保留 narration 原始值
  - 从 `narration: scene.dialogue || scene.narration` 改为优先使用 `scene.narration`
  - 防止 dialogue 覆盖 narration 导致精简后截断

- **`Stage 11 明亮约束`**: 条件注入
  - generic 模式：自然光或柔和室内照明
  - Nirath 模式：Aurelius5800K + Silvana6500K 双恒星

### 2. `systems/narration-auto-trim.js`（1处修改）

- **`trimRound` 兜底截断后**：添加句号保护
  - 如果原始文本以句号结尾但精简后未以句号结尾，自动补全"。"
  - 防止截断在非标点字符（如"状"、"了"）

### 3. `systems/prompt-tier-architecture.js`（1处修改）

- **`_buildTier1`**: 默认 sceneCore 从 `Nirath alien landscape` → `真实场景`
- 影响：当 LLM 返回对象或 sceneName 缺失时，不再注入 Nirath

### 4. `systems/prompt-builder.js`（1处修改）

- **`_getEnvironmentDescription`**: 默认环境从 `alien landscape` → `realistic medical setting`
- 影响：fallback 环境描述不再包含外星元素

### 5. `systems/worldview-scene-manager.js`（1处修改）

- **`getSceneVisualCore`**: 无数据回退从 `alien landscape` → `realistic scene`
- 影响：场景 ID 未匹配时不再默认 Nirath

## 关键经验教训

### 1. API 认证不仅是 Key
- Kimi Plugin 需要专属 Headers：`User-Agent: Kimi Claw Plugin` + `X-Msh-Device-Name: openclaw-kimi-embedding`
- 端点 `agent-gw.kimi.com/coding` 与 `api.moonshot.cn` 的认证体系不同
- Temperature 限制：`kimi-k2p6` 仅允许 `temperature=1`，其他值直接 400

### 2. Nirath 污染是多模块的系统性问题
- 不能只修一处，需要全局扫描所有含 "alien"、"Nirath"、"双恒星"、"5800K" 的默认值
- 最容易遗漏的位置：fallback 路径、默认值、无数据回退
- 修复策略：所有模块添加 `this.mode !== 'nirath'` 守卫，或默认值改为真实场景

### 3. Narration 精简是双刃剑
- 自动精简在标点处截断是正确的，但兜底截断（按字符数）可能破坏语义完整性
- 解决方案：精简后检查原始文本是否以句号结尾，如果精简后丢失句号则补全
- 同时：Stage 7 不要覆盖原始 narration 为 dialogue（dialogue 通常更长，精简后截断风险更高）

### 4. 角色推断必须与模式绑定
- generic 模式（纪录片/科普）的角色推断逻辑与 Nirath 模式（奇幻/异兽）完全不同
- generic 模式应推断真实角色（主持人、观众、专家），Nirath 模式推断虚构角色（AgentX、异兽）
- 不能共用一套角色推断逻辑
