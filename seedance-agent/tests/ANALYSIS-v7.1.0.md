
## 二、代码级 Bug（本轮已修复 2 个，剩余 N 个）

### 2.1 已固化修复

| # | 文件 | Bug | 影响 |

| 2 | `delivery-engine.js:15` | `skills/` 路径前缀冗余 | 后期合成失败 |

### 2.2 仍存在的代码问题

#### 🔴 P0: character-manager.js 不支持 `--output` 参数
- **现象**: CLI 传入 `--output /path/to/file`，实际输出到 `~/Seedance-Characters/C01-创业者/`
- **影响**: pipeline 脚本检查失败，需手动修正路径
- **建议**: 要么支持 `--output` 参数，要么在文档中明确说明输出目录固定

#### 🔴 P0: v6-adapter.js 命令注入空参数
- **现象**: `pitch-evaluation.js evaluate --input  --output ./projects/...`（`--input` 后有两个空格）
- **影响**: 集成测试中 pitch-evaluation 可能读取空输入
- **代码位置**: `v6-adapter.js` 构建命令时未做空值检查

#### 🟡 P1: model-decision-engine.js 的 `analyzeCreativeIntent()` 是纯规则匹配
- **现象**: `if (text.includes('热血')) return {...}`，不是 LLM 分析
- **影响**: 用户用自然语言描述需求时，意图识别准确率受限
- **建议**: 接入轻量 LLM（或保留规则 fallback）做意图提取

#### 🟡 P1: styleDNA 混合计算是字符串拼接，非数学计算
- **现象**: `"[混合] 8:1 ×60% + 3:1 ×30% + 3:1 ×10%"`
- **影响**: 下游模块无法直接解析为数值做渲染参数
- **建议**: 输出结构化数值 `{lightRatio: 6.7, shadowDensity: 0.72}`

#### 🟡 P1: 状态机中 `styleChromosome` / `styleFootprint` / `styleSRS` 始终为 null
- **现象**: 集成测试输出的 state 中这三个字段永远是 null
- **影响**: v7.0 宣称的风格系统 partially unimplemented

## 三、内容质量优化（业务层）

### 3.1 镜头多样性不足

TC01 分镜表问题：
```
S01: 全景 + 平视 + 手持（起）
S02: 全景 + 平视 + 手持（起） ← 重复！
S03: 中景 + 平视 + 环绕（承）
S04: 中景 + 平视 + 环绕（承） ← 重复！
S05: 特写 + 倾斜 + 摇摄（转）
S06: 特写 + 倾斜 + 摇摄（转） ← 重复！
```

**问题**: 相邻镜头景别/角度/运动完全一致，缺乏视觉节奏变化。
**建议**: shot-design 模块增加"相邻镜头差异化"约束（至少改变一个维度）。

### 3.2 角色资产信息缺失

```yaml
# 02-assets.md 实际输出
C01 — 创业者
  物种: 未知物种      ← BUG
  特征: (空)
  标志性元素: (空)    ← 缺失
```

**根因**: `character-manager.js` 的 `generateCharacter()` 未填充 `traits` 和 `signatureElements`。
**影响**: 下游分镜生成时无法引用角色的标志性视觉元素。

### 3.3 对白密度不均衡

| TC | 总镜头 | 有对白镜头 | 密度 |
|----|--------|----------|------|
| TC01 逐光者 | 8 | 1 | 12.5% |
| TC02 午后时光 | 16 | 4 | 25% |
| TC03 暗房 | 12 | 1 | 8.3% |
| TC04 破晓之舞 | 8 | 2 | 25% |

**问题**: 悬疑类（TC03）对白密度过低，热血类（TC01）也偏低。
**建议**: `dialogue-engine.js` 应根据 genre 和 platform 设置对白密度基线（悬疑类应更高）。

### 3.4 S08 时长异常

TC01 中 S08 时长为 9 秒（21s-30s），而其他镜头都是 3 秒。
**问题**: 最后一镜过长，破坏剪辑节奏。
**建议**: 分镜生成器增加"单镜时长上限约束"（如 5 秒）。

## 四、性能与资源优化

### 4.1 项目目录膨胀

```bash
$ ls projects/ | wc -l
> 40+ 个目录（每次测试创建 4 个 TC × 多次运行）
```

**问题**: 无自动清理机制，磁盘空间持续增长。
**建议**: 
- 测试脚本添加 `cleanup()` 函数（保留最新 2 批次）
- 或迁移临时产出到 `/tmp/seedance-tests/`

### 4.2 LLM 调用层

```javascript
// agent-loop.js
const DECISION_CONFIG = {
  cacheEnabled: true,
  cacheTTLMs: 60000  // 1分钟缓存
};
```

**问题**: 1 分钟缓存对视频制作场景偏短（一个决策周期通常 >1 分钟）。
**建议**: 延长至 5-10 分钟，或按 `projectId + stateHash` 做持久化缓存。

### 4.3 并发控制

```javascript
// tool-pool.js
maxConcurrentAgents: 7  // 固定值
```

**问题**: 未根据实际 API quota 动态调整。
**建议**: 从 config-center 读取实时 quota 动态调整并发数。

## 五、架构层优化建议

### 5.1 降级路径不够平滑

```javascript
// agent-loop.js
fallbackAction: "若故事方案生成受阻，降级为纯文字分镜脚本交付"
```

**问题**: 只有 story-engine 有 fallback，其他模块（shot-design、render-engine）无降级策略。
**建议**: 每个 Tier-1 工具都定义 fallback chain（如 render-engine 降级为静态帧序列）。

### 5.2 飞书通知未实际发送

```javascript
// feishu-notifier.js（集成测试中）
[PermissionGate] 已发送飞书通知: render-engine
```

**问题**: 测试显示"已发送"但队长实际未收到（或通知内容过于简略）。
**建议**: 
- 检查 feishu-notifier.js 的 webhook/token 配置
- 通知内容应包含：项目名、当前进度%、需要确认的操作、预计成本

### 5.3 测试覆盖率缺口

当前测试覆盖：

- ✅ 状态机（init/transition/rewind/fork）

- ✅ 工具池（批量执行）
- ❌ **Context Collapse 逻辑**（未测试）
- ❌ **A/B 测试分支**（未测试）
- ❌ **预算超限场景**（未测试）
