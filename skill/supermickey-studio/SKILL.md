# SuperMickey 视频提示词生成器

## 核心运行原则（最高优先级）

**LLM 环节由本 Agent 自身模型承担**：SuperMickey 系统中所有依赖 LLM 的模块（意图解析、剧本生成、场景卡 Agent、镜头设计 Agent、提示词引擎 Agent、导演审片 Agent、产品事实校验、营销技能路由、数据挖掘引擎五 Agent 等）一律由执行本技能的 Agent 用自己的模型能力就地运行，严格按照拉取到的最新代码中各模块的规范、字段定义、质量门执行。不需要、不等待、不尝试任何外部 API 密钥（ARK_API_KEY / KIMI_API_KEY 等）。

**严禁降级运行**：禁止跳过任何模块、禁止以"简化版/示意版/规范级运行"代替完整执行。必须按系统完整流水线跑完全部环节，每个环节的交付物一个不少，每个镜头的字段一个不缺，导演审片必须真实执行并给出评分结论。

**不执行视频渲染**：视频渲染环节一律跳过（用户后续手动渲染）。不需要配置渲染管线、不需要调用 Seedance 或任何渲染引擎。最终交付物止步于"镜头完整提示词"文本本身（定妆照为静态图片环节，按定妆照纪律执行，不在此限制内）。

**真实代码核验**：凡系统提供可执行校验的环节（预检、交付守卫、作品级校验、事实闸机、定妆照闸机、时长分配、技能路由、档案 Schema 校验），必须用 node 真实运行系统代码取得结果，禁止凭印象声明"已校验"。

**确认机制双模说明**：系统以 CLI 方式运行全流程时，每个主要环节（商品情报档案/创意主题/业务需求/PRD/镜头提示词/定妆照）均设人工确认门，逐一等待人工 approve 后才放行下游——这是系统生产纪律。但**本技能调用方式下，由执行 Agent 按流水线连续跑完全部环节，各环节交付物照常产出，不中断等待用户确认**；技能文件中出现"确认单"字样时，其用途是让 Agent 自检与向用户展示结果，而非等待批准的闸机。

## 执行流程（严格按顺序执行）

### Step 0：前置检查（不可跳过）

1. 克隆仓库默认分支最新代码（仓库已私有化，必须带令牌认证；优先 git clone 带认证头，失败则用 API 压缩包兜底）：
   `git clone --depth 1 https://github.com/geniusdapeng-collab/super-mickey.git`
   默认分支为 master，clone 得到的 HEAD 即"最新系统代码"。
2. 确认当前版本号：只读克隆下来的 `package.json` 的 `"version"` 字段，记录于执行日志。该字段是 SuperMickey 系统版本号的唯一权威来源。
3. 运行规范预检：`node scripts/agent-preflight.js`，退出码必须为 0；非 0 先修复再继续。
4. 阅读并理解当前版本的系统架构、约束栈、提示词规范、输出格式定义、平台蓝图（hyperreality-system/config/platform-profiles.js）。

> ⚠️ 版本识别强制约束：
> - 禁止通过 Git tag 列表、tag 版本号大小比较、文档标题、目录名、子系统内部编号推断"最新版本"。
> - 禁止 `git checkout` 任何 tag 或分支来获取"最新代码"——默认分支 HEAD 就是最新。
> - 仓库内出现的任何子系统历史内部编号与 SuperMickey 系统版本无关，一律忽略。
> - 如果因网络或权限原因无法拉取最新代码，必须明确告知用户并停止执行，禁止基于记忆或旧版本继续运行。
> - 测试目录中的镜头骨架（如 marketing-m*-test.js）只是模块单元测试夹具，禁止当作产物结构规范依据；产物结构以主管线（hyperreality-system/index.js）与预检规范卡为准。

### Step 1：输入类型识别

接收用户提供的主题/故事/营销 Brief，判定输入类型：

- **故事/主题类**：走电影叙事管线（创意主题生成 → 业务需求洞察 → PRD → 镜头提示词）。
- **社媒营销类**（含商品名/平台名/种草/带货/投放等特征）：走社媒营销管线，必须执行本技能"营销专属纪律"全部条款（见下文专章），且**必须先执行节点 0**。

### Step 2：运行 SuperMickey 系统

基于拉取到的最新代码，按系统内部流程执行，关键节点必须逐项产出并即时输出交付物（输出后继续推进，不中断等待任何确认）：

**节点 0：珍妮纺织机·商品情报挖掘（社媒营销类强制，全链路第一环节）**
- 触发条件：输入含商品名/营销 Brief 时**必须最先执行本节点**，早于创意主题生成；纯故事类任务跳过本节点并明确说明。
- 真实运行数据挖掘引擎（`hyperreality-system/engines/data-mining-engine/`，spec 模式）：
  1. `engine.plan(input)` 产出三份采集任务书（A1 商品情报/A2 用户评价/A3 竞品侦察）；
  2. 本 Agent 按任务书就地联网检索并回填（严守任务书 discipline：评价原文回填、无源事实不回填、商品图禁 AI 图冒充）；
  3. `engine.assemble(...)` 真实运行：五站流水线（采集→挖掘→侦察→交叉验证→装订），Schema 校验失败即拒收。
- 输出（全任务最先交付的两份文件）：
  - `00_商品情报档案.md`：商品身份与价格带（含置信度）、官方卖点、商品图清单、使用场景、用户称赞点/吐槽点/原话、优缺点（用户共识与官方宣称分区）、竞品矩阵与差异化空位、钩子原料、情报缺口（gaps 逐条公示）、溯源清单（provenance）、交叉验证报告。
  - `00_商品主图清单.md`：英雄照（编号 + URL + 角度 + 授权风险）+ 全部参考图 manifest，明确标注"仅作定妆照参考图，须核对真实性与型号一致性"。
- **连续执行（技能模式）**：两份文件产出即视为情报层就绪，Agent 生成档案确认单用于自检与向用户展示结果，**随后直接向下游推进，不中断等待用户确认**（人工确认门仅在系统 CLI 运行模式下生效，见"核心运行原则·确认机制双模说明"）。
- 档案命中复用（同商品历史档案未过期）时直接加载消费并注明"[复用]"，连续推进不中断。

**节点 A：创意主题生成（Theme Generation / Brief 确认）**
- 运行系统的创意主题生成模块（营销类运行 MarketingBriefParser 生成 Brief 确认单；情报档案已就绪后，Brief 由档案摘要卡自动回填空缺字段）
- 输出：`01_创意主题生成.md`
- 内容要求：包含核心创意概念、视觉关键词、情绪基调、叙事钩子；营销类附 Brief 确认单（盒式）与平台蓝图继承表

**节点 A+：产品事实校验（社媒营销类强制，阻断式）**
- 详见"营销专属纪律"第 1 条。情报档案已就绪后，调研记录优先引用档案中的已验证事实与溯源清单。校验不通过：修改创意后重新校验，禁止带冲突进入下游。

**节点 B：业务需求洞察（Business Insight）**
- 运行系统的业务需求分析模块
- 输出：`02_业务需求洞察.md`
- 内容要求：包含受众画像、传播场景、差异化卖点、商业锚点；用户原始输入原样直通（未改写未省略）；营销类必须继承事实红线，洞察结论须挂情报档案证据锚点

**节点 C：PRD 文档（Product Requirements Document）**
- 运行系统的产品需求文档生成模块
- 输出：`03_PRD.md`
- 内容要求：包含项目定义、产品定位、创意核心、视觉规格、音频规格、角色系统、场景规划、制作约束、受众定位、参考案例、交付标准；营销类制作约束章节必须原样继承事实红线与时长分配表，卖点→镜头映射须有情报档案依据

### Step 3：镜头提示词生成与输出

- 基于 PRD 运行系统的镜头提示词生成模块
- 输出：`04_镜头完整提示词.md`
- 强制要求：
  - 每个镜头的提示词必须严格符合 SuperMickey 规范（以拉取到的最新代码中的规范定义为准）
  - 内容镜头 30 字段：01.【语言约束】至 30.【角色一致性】；片头镜头加 5 专属字段：【主标题内容】【副标题内容】【标题动画设计】【标题字体设计】【开场音频设计】
  - 序号+独立行排版，序号连续不得断号重号；字段正文全部中文（英文仅允许【负面约束】固定短语与【基础】质量锚点词）
  - 台词纪律：【台词】[时间戳] 角色 动作触发, 情绪 说:"台词"；台词必须是角色直接对话（带角色名），禁止画外音/旁白；数据层无台词的镜头（如纯标题卡片头）禁止出现【台词】字段（含"本镜无台词"等占位说明）；速率与占比按平台蓝图档（蓝图未覆盖时按系统全局档）
  - 如果系统规范中有特殊字段（如 seedance_render_tag、cg_style_anchor 等），必须完整保留
  - 禁止省略、禁止简化、禁止用"略"或"同上"代替
  - 长度两阶段口径：组装目标 2470-3000 字符，硬上限 3000；精炼后交付 ≥1200 且 ≤3000（精炼环节 field-content-refiner 六类规则必须执行）
- 交付校验（双保险，真实运行）：
  - 逐镜 PromptDeliveryGuard.verify 全部 PASS（守卫已兼容"序号+独立行"排版，最终文本可直接核验）
  - 作品级 PromptDeliveryGuard.verifyPackage PASS：片头在场、单镜时长落蓝图时长带、镜头数>2 时禁止全部同长、总时长与目标容差 ±15%
  - 两项全绿才允许交付；任一不过，修复后重新校验

### Step 4：定妆照环节（含商品时强制）

- 角色定妆照：按 portrait-studio 角度包执行（lead 8 角度按优先级裁剪渲染，supporting 4 角度，prop/background 按需），注入视觉系统锚点。
- 商品定妆照：必须执行"营销专属纪律"第 2 条的真实参考图链路，禁止凭空生成。**情报档案已就绪后，搜图阶段直接消费 `00_商品主图清单.md` 的参考图 manifest（executor=prefilled，免重复检索）**，执行方仅核对图片真实性与型号一致性。

### Step 5：Bug 与优化问题扫描

在执行 Step 2-4 的过程中，同步进行以下检查：

| 检查项 | 检查内容 |
|--------|----------|
| 代码运行异常 | 是否有报错、中断、非预期输出 |
| 规范偏离 | 输出格式是否与最新版 SuperMickey 规范一致 |
| 字段缺失 | 关键字段是否被遗漏或为空 |
| 逻辑矛盾 | 前后环节产出是否存在冲突（含创意前提与产品事实冲突、情报档案与 Brief 冲突） |
| 可优化点 | 是否有明显可提升效率或质量的改进空间 |

- 如果发现任何问题：
  - 输出：`05_Bug修复与优化建议.md`
  - 内容要求：问题描述（现象+影响）、根因分析、可直接复制粘贴使用的修复代码（如适用）、验证方式
- 如果未发现任何问题：
  - 本文件不输出
  - 在最终回复中明确说明："本次执行未发现 Bug 或待优化项，系统运行正常。"

## 营销专属纪律（社媒营销类输入强制，逐项不可跳过）

### 1. 产品事实校验闸机（ProductTruthChecker，阻断式）

- 位置：创意主题生成完成之后、业务需求清单确认之前。事实基线是上游输入，洞察与 PRD 必须建立在校验过的事实上。
- 情报档案已就绪后，调研记录优先引用档案已验证事实与溯源（provenance），避免重复调研；档案未覆盖的维度照常联网补齐。
- 支持任意商品与服务类型：调研维度为三层开放结构——通用底座 4 维（使用前提与依赖条件/能力效果边界/官方宣传口径/价格与购买履约方式，一切商品服务必查）+ 品类扩展包（硬件/软件SaaS/食品/美妆/服饰家居/服务六组，按 category 关键词模糊归类，可命中多组取并集）+ Brief 自定义维度。品类未命中扩展包时，必须按商品特性补充 2-4 个自定义调研维度，禁止只做通用底座调研。
- 执行三段式（真实运行 product-truth-checker.js）：
  1. `buildResearchTask(brief)` 取调研任务，按解析出的维度联网调研，信源优先级：官网/官方社媒 > 官方旗舰店/官方客服 > 权威媒体 > 第三方评测；每条事实必须带信源。
  2. `verify({brief, researchNotes, creative})` 产出事实基线（能力含前提/使用前提/边界/官方口径/禁用宣称）。
  3. 创意前提冲突检查：命中禁用宣称（如"脱离手机/App 独立使用"）→ 阻断，修改创意后重新校验；禁止带冲突进入节点 B。
- PRD 制作约束章节必须原样继承 factRedLines（事实红线），镜头设计不得突破。
- 铁律：宣称不得超出官方口径；创意前提必须与产品真实使用前提自洽；演示流程按官方已验证交互复刻，禁止"演示超纲"。

### 2. 商品定妆照真实参考图链路（禁止凭空生成）

- 商品类型判定（自动，按 category 或 assetType 归类）：
  - **实物类**：走商业摄影链路——参考图为真实商品实拍（官网/旗舰店/官方社媒，≥2 张不同角度）；处理为抠图→白底基准图→光影统一；视角包为商业摄影 5 视角。
  - **服务/虚拟类**（服务/课程/SaaS/本地生活/金融等无实物外观）：走品牌履约链路——参考图为官方品牌物料/官方界面截图/门店实拍（≥2 张、可溯源）；处理为裁切规范化+光影统一（禁止抠图去背景，服务场景需保留环境证据）；视角包为服务 5 视角（品牌主视觉/履约场景/界面特写/人员形象/用户场景）。
- 情报档案已就绪后，参考图优先消费 `00_商品主图清单.md` 的 manifest（免重复检索），仅做真实性与型号一致性核对；不足部分按原链路补检。
- 阶段3 stylization 启动前：真实运行 checkStylizationReady 闸机（参考图不足/缺来源/AI 图冒充/基准图缺失 → 阻断，两类商品通用）。
- 生成时必须以参考图引导（本地图先转公开 URL 再作参考图传入），外观/品牌视觉 100% 忠于实物与官方物料；AI 生成图禁止冒充参考图。
- 视觉资产绑定编号（heroImageId）逐镜写入【商品锚点】：实物类字段为"英雄照实拍绑定+材质锚点"，服务类自动变形为"品牌视觉资产绑定+视觉识别锚点"；正式渲染前以真实素材回填。
- 工具失败时换手段（浏览器访问电商页取图等），禁止退化为文字描述生成。

### 3. 镜头结构铁律（营销片与叙事片同样适用）

- 片头在场：每部作品必须含片头镜头（shotId=S00，sceneType=opening）。片头豁免营销场景链锚点字段，但 27 个适用标准字段 + 5 个片头专属字段一个不缺；片头无台词时不含【台词】字段。
- 时长分配：镜头时长必须用 MarketingDurationBridge.allocate 真实分配（职能→分配器角色映射+蓝图时长带收敛），禁止手写均分；单镜时长全部落在平台蓝图时长带内；分配结果写入 PRD 场景规划表。
- 营销场景链：营销内容镜逐镜强制在场【商品锚点】（实拍绑定编号+材质锚点+LOGO锚点+特写锚点）、【商品一致性】、【配乐】（卡点映射+版权策略，尾镜高潮点对齐）、【画面文字设计】（字幕条/卖点花字≤12字/安全区声明）。
- 营销技能路由：每镜职能必须真实运行 MarketingSkillRouter 匹配技能（禁止虚构技能命中），命中技能的执行要点与禁忌注入该镜导演意图；情报档案已就绪后，钩子类技能选型引用档案 hook_material。

## 禁止事项

1. 禁止基于记忆或缓存的旧版本代码执行，必须先拉取最新版
2. 禁止跳过中间节点直接输出最终提示词（含节点 0 情报挖掘与产品事实校验闸机）
3. 禁止在关键产出物中使用"详见上文"、"同上"等省略表述
4. 禁止隐瞒或淡化发现的 Bug，必须如实记录
5. 禁止输出任何版本号、变更记录、修订痕迹、反思内容到交付文件中
6. 禁止手写均分镜头时长、禁止虚构技能命中、禁止虚构"已校验"结论
7. 禁止凭空生成商品定妆照、禁止 AI 生成图冒充真实参考图
8. 禁止创意前提与产品真实使用前提矛盾（事实红线一票否决）
9. 禁止无台词镜头出现【台词】字段（含占位说明文字）
10. 禁止把测试目录中的镜头骨架当作产物结构规范
11. 社媒营销类任务禁止跳过节点 0 直接生成主题；禁止交付无溯源、无置信度的商品情报
12. 禁止在节点 0 未真实产出商品情报档案前，让下游凭空编造商品信息、评价或竞品情报
