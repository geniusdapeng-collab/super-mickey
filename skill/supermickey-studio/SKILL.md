# SuperMickey 视频提示词生成器

## 核心运行原则（最高优先级）

**LLM 环节由本 Agent 自身模型承担**：SuperMickey 系统中所有依赖 LLM 的模块（意图解析、剧本生成、场景卡 Agent、镜头设计 Agent、提示词引擎 Agent、导演审片 Agent 等）一律由执行本技能的 Agent 用自己的模型能力就地运行，严格按照拉取到的最新代码中各模块的规范、字段定义、质量门执行。不需要、不等待、不尝试任何外部 API 密钥（ARK_API_KEY / KIMI_API_KEY 等）。

**严禁降级运行**：禁止跳过任何模块、禁止以"简化版/示意版/规范级运行"代替完整执行。必须按系统完整流水线跑完全部环节，每个环节的交付物一个不少，每个镜头的字段一个不缺，导演审片必须真实执行并给出评分结论。

**不执行渲染**：渲染环节一律跳过（用户后续手动渲染）。不需要配置渲染管线、不需要调用 Seedance 或任何渲染引擎。最终交付物止步于"镜头完整提示词"文本本身。

**规范只有一个出口**：系统规范（字段结构、长度口径、语速基准、执行纪律）一律以 `node scripts/agent-preflight.js` 输出的规范卡为准，规范卡实时解析自引擎代码与 config 真源。本技能不登记任何规范细节，禁止凭记忆或本文件复述规范。

## 执行流程（严格按顺序执行）

### Step 0：前置检查（不可跳过）

1. 克隆仓库默认分支最新代码：
   `git clone --depth 1 https://github.com/geniusdapeng-collab/super-mickey.git`
   默认分支为 master，clone 得到的 HEAD 即"最新系统代码"。
   若当前工作目录已是该仓库的工作副本且为默认分支 HEAD，可直接使用，不必重复克隆。
2. 确认当前版本号：只读 `package.json` 的 `"version"` 字段，记录于执行日志。
   该字段是 SuperMickey 系统版本号的唯一权威来源。
3. 运行规范预检（规范唯一出口，不可跳过）：
   `node scripts/agent-preflight.js`
   预检通过后将输出的规范卡作为本次执行的唯一规范依据；
   预检阻断（非零退出）时必须停止执行并向用户报告阻断项，禁止绕过。

> ⚠️ 版本识别强制约束：
> - 禁止通过 Git tag 列表、tag 版本号大小比较、文档标题、目录名、子系统内部编号（如 seedance 生产系统的 v6.x / v6.6.x）推断"最新版本"。
> - 禁止 `git checkout` 任何 tag 或分支来获取"最新代码"——默认分支 HEAD 就是最新。
> - 仓库内出现的任何 v6.x 字样均为子系统历史内部编号，与 SuperMickey 系统版本无关，一律忽略。
> - 如果因网络或权限原因无法拉取最新代码，必须明确告知用户并停止执行，禁止基于记忆或旧版本继续运行。

### Step 1：主题/故事输入接收

接收用户提供的主题或故事内容。

### Step 2：运行 SuperMickey 系统

基于拉取到的最新代码，按系统内部流程执行，关键节点必须中断并输出交付物。各节点交付物的字段结构以规范卡【中间环节交付物格式】为唯一权威（规范卡实时解析自引擎生成函数），禁止按本技能或任何文档自带的格式清单执行：

**节点 A：创意主题生成（Theme Generation）**
- 运行系统的创意主题生成模块
- 输出：`01_创意主题生成.md`
- 内容要求：包含核心创意概念、视觉关键词、情绪基调、叙事钩子

**节点 B：业务需求洞察（Business Insight）**
- 运行系统的业务需求分析模块
- 输出：`02_业务需求洞察.md`
- 内容要求：包含受众画像、传播场景、差异化卖点、商业锚点

**节点 C：PRD 文档（Product Requirements Document）**
- 运行系统的产品需求文档生成模块
- 输出：`03_PRD.md`
- 内容要求：包含功能需求、非功能需求、镜头清单、技术规格、验收标准

### Step 3：镜头提示词生成与输出

- 基于 PRD 运行系统的镜头提示词生成模块
- 输出：`04_镜头完整提示词.md`
- 强制要求：
  - 每个镜头的提示词必须严格符合规范卡输出的当前规范（字段清单、字段顺序、长度两阶段口径、语速基准、语言约束等）
  - 交付排版为"序号+独立行"（01.【字段名】逐行排列）；每镜头标注字段数（内容镜头 N/30、片头镜头 N/35，以规范卡实况为准）
  - 【台词】字段严格按规范卡格式渲染（[时间戳] 角色 trigger, emotion 说:"line"）；无角色对话镜头标注不虚构台词；营销口号/字幕归入【画面文字设计】
  - 如果系统规范中有特殊字段（如 seedance_render_tag、cg_style_anchor 等），必须完整保留
  - 禁止省略、禁止简化、禁止用"略"或"同上"代替

### Step 3.5：定妆照生成（v2.8.0 起为固定环节）

- 运行 PortraitStudio 引擎（`hyperreality-system/engines/portrait-studio/`）
- 双模式：
  - **交互模式（默认）**：先输出定妆照生成计划（角色分级与角度清单、商品分支说明），主动询问用户确认后再执行
  - **批量模式**：用户明确"无偏好/直接跑/批量"时，无需询问，自动决策直接生成
- 强制要求：
  - 角色按戏份重要性分级配角度（主角 8 角度/配角 4/客串 2，以引擎分级结果为准）；**所有角色（含客串）一律走"主锚点先行+参考图驱动"工艺**：先生成正面全身主锚点，其余角度以主锚点为参考图生成，禁止纯 prompt 并行生成多角度
  - 商品走分支链路：联网搜真实参考图（遵守引擎 requirements，含系列化产品型号甄别）→ 抠图/白底/光影统一 → 风格化 5 视角；商品外观 100% 锚定实物参考图
  - 单张生成失败执行退避重试（冷却 45s 重试最多 3 次；连续 2 张失败冷却 90s；3 次仍失败标记 failed 记入 manifest 并继续，绝不中断整批）
  - **定妆照必须实际渲染成图片并逐张直接展示给用户**，禁止只交付生成提示词或文件路径
- 输出：`portraits/`（定妆照集：manifest.json + 定妆照集.md + 全部图片文件）

### Step 4：Bug 与优化问题扫描

在执行 Step 2 和 Step 3 的过程中，同步进行以下检查：

| 检查项 | 检查内容 |
|--------|----------|
| 代码运行异常 | 是否有报错、中断、非预期输出 |
| 规范偏离 | 输出格式是否与规范卡一致 |
| 字段缺失 | 关键字段是否被遗漏或为空 |
| 逻辑矛盾 | 前后环节产出是否存在冲突 |
| 可优化点 | 是否有明显可提升效率或质量的改进空间 |

- 如果发现任何问题：
  - 输出：`05_Bug修复与优化建议.md`
  - 内容要求：
    1. 问题描述（现象 + 影响）
    2. 根因分析
    3. 可直接复制粘贴使用的修复代码（如适用）
    4. 验证方式
- 如果未发现任何问题：
  - 本文件不输出
  - 在最终回复中明确说明："本次执行未发现 Bug 或待优化项，系统运行正常。"

## 禁止事项

1. 禁止基于记忆或缓存的旧版本代码执行，必须先拉取最新版
2. 禁止跳过中间节点直接输出最终提示词
3. 禁止在关键产出物中使用"详见上文"、"同上"等省略表述
4. 禁止隐瞒或淡化发现的 Bug，必须如实记录
5. 禁止输出任何版本号、变更记录、修订痕迹、反思内容到交付文件中
6. 禁止以生成提示词或文件路径代替定妆照图片交付，定妆照必须实际渲染并逐张展示
