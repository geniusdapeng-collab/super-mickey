# 神兽档案库技术白皮书 v1.0

> **产品定位**: 山海经神兽的数字化引擎，将神兽从"静态知识"转化为"视频生产链路的活性原料"
> **设计理念**: 神兽不是数据库条目，是每一次渲染时必须被正确调用、精确注入、严格校验的智能资产
> **当前规模**: 支持40只神兽，架构预留至200只
> **核心产出**: 标准化Prompt片段 + 一致性校验 + 运镜方案 + 场景描述

---

## 一、产品定位：为什么需要神兽档案库？

### 问题痛点（队长实际踩过的坑）

| 问题 | 后果 | 案例 |
|------|------|------|
| **角色形象混乱** | 同一只神兽每镜长得不一样 | 帝江传EP01：主角小G三四个不同形象，混入阿凡达女主 |
| **Prompt随意编造** | AI自由发挥导致神兽特征变异 | "烛龙"变成蓝色、"凤凰"长出蜥蜴尾巴 |
| **环境不匹配** | 神兽出现在错误栖息地 | 应龙在"永夜裂谷"（应该在云雷高原） |
| **运镜不专业** | 超巨型神兽用特写，丢失震撼感 | 烛龙用close_up，完全没有"降临"巨物美学的压迫感 |
| **世界观割裂** | 混入现代科技元素 | 神兽背上出现"机甲"、"飞船" |

### 解决思路

**"神兽档案库 = 神兽的'定妆照 + 身份证 + 使用说明书'"**

```
传统方式                          神兽档案库方式
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
人工写Prompt                        档案自动注入Prompt
"烛龙，红色的，很大..."            标准化60字精确描述
每次重新描述                        每镜引用同一份档案
无一致性检查                        5维自动校验拦截
运镜凭感觉                          基于体型/类型智能推荐
```

### 三层详解

#### 1. 数据层：神兽的"数字身份证"

**每个神兽一张JSON档案，40+标准字段：**

```
📁 beast-database/beasts/
   ├── zhu-long.json     (烛龙)
   ├── ying-long.json    (应龙)
   ├── feng-huang.json   (凤凰)
   ├── bai-ze.json       (白泽)
   └── ...
```

**核心字段结构：**
```json
{
  "id": "zhu-long",                    // 唯一标识
  "catalogNo": "01",                  // 图鉴编号
  "name": {
    "chinese": "烛龙",                // 中文名
    "pinyin": "Zhú Lóng",            // 拼音
    "aliases": ["烛九阴", "烛阴"]     // 别名（用于Prompt匹配）
  },
  "classification": {
    "tier": "创世神祇",               // 级别（创世/上古/四方/异界）
    "category": "时空主宰",           // 分类（战神/智慧/凶兽等）
    "originText": "《山海经·大荒北经》" // 出处
  },
  "nirathStatus": {
    "isNative": true,                  // 是否Nirath原生
    "habitat": "永夜裂谷",            // 栖息地
    "ecosystemRole": "星球级调节器"     // 生态角色
  },
  "visualIdentity": {
    "coreDescription": "人面蛇身而赤，身长千里",  // 核心描述
    "bodyPlan": "人首蛇身",           // 身体结构
    "colorPalette": ["赤红", "金色"],  // 主色调
    "scale": "超巨型",                // 体型等级
    "texture": "鳞片",                // 材质
    "signatureFeatures": ["竖直双目", "身长千里"], // 标志性特征
    "promptFragments": {               // 预切分Prompt片段
      "head": "人面头部眉目深邃",
      "body": "绵延蛇身长达千里",
      "eyes": "竖直双目开合决定昼夜",
      "special": "口中衔持永恒火精"
    },
    "portraitConfig": {                // 定妆照配置
      "model": "seedream-5-0",
      "style": "超写实CG渲染，东方神话史诗"
    }
  },
  "abilities": [
    {
      "name": "掌控昼夜",
      "description": "睁眼为白昼，闭眼为黑夜",
      "visualCue": "双目开合伴随光芒爆发",
      "nirathSciFi": "恒星能量调节",
      "rarity": "legendary"
    }
  ]
}
```

**关键设计决策：**
- **Prompt预切分**: 在数据层就把外观描述切成head/body/eyes/special，运行时按需组装
- **别名体系**: "烛龙"也叫"烛九阴""烛阴"，三个名字都能触发同一份档案
- **颜色严格定义**: "赤红"就是赤红，不是"红色""朱红""暗红"
- **体型分级**: 超巨型/巨型/大型/中型/小型，决定运镜方案

#### 2. 耦合层：五大引擎（神兽"活性化"核心）

**这5个引擎让死数据变成活的Prompt：**

##### 引擎1: Prompt注入器 (beast-prompt-injector.js)

**功能**: 把剧本中的神兽名字，自动替换为精确的Prompt描述

**运行机制：**
```
输入: "小G在永夜裂谷遇见了烛龙"
        ↓
Step 1: 扫描文本 → 匹配到 "烛龙"
        ↓
Step 2: 加载档案 → 读取 zhu-long.json
        ↓
Step 3: 组装Prompt片段
        
  compact模式 (40-60字):
  "赤红烛龙——人面蛇身绵延千里，竖直双目如炬"
  
  detailed模式 (100-120字):
  "赤红烛龙横亘于永夜裂谷深处，人面蛇身绵延千里..."
        ↓
Step 4: 嵌入剧本
        ↓
输出: "小G在永夜裂谷遇见了赤红烛龙——人面蛇身绵延千里，竖直双目如炬"
```

**多神兽同框处理：**
```
输入: "烛龙与应龙在云雷高原对峙"
        ↓
检测2只神兽 → 加载2份档案
        ↓
组装同框Prompt:
"赤红烛龙... [左] vs 金黄应龙... [右]
 构图: 双主体对称，各占画面1/2
 比例: 烛龙千里蛇身 vs 应龙百米翼展
 交互: 能量碰撞形成彩虹电弧"
```

---

##### 引擎2: 一致性守卫 (beast-consistency-guard.js)

**功能**: 确保神兽在每一镜都长得一样，防止AI"自由发挥"

**5维检查体系：**

| 维度 | 检查内容 | 违规示例 | 拦截方式 |
|------|----------|----------|----------|
| **颜色** | 主色调是否在允许列表 | "蓝色烛龙" → ❌ | 替换为"赤红" |
| **形态** | 身体结构是否变形 | "西方龙双翼" → ❌ | 替换为"人首蛇身" |
| **能力** | 核心能力是否突变 | "烛龙吐水" → ❌ | 删除/替换 |
| **规模** | 体型等级是否跳跃 | "烛龙缩小到中型" → ❌ | 强制恢复超巨型 |
| **栖息地** | 是否出现在正确环境 | "应龙在永夜裂谷" → ❌ | 警告建议云雷高原 |

**规则库示例：**
```javascript
const COLOR_RULES = {
  'zhu-long': {
    primary: ['赤红', '暗红'],
    secondary: ['金色', '暗紫'],
    forbidden: ['蓝色', '绿色', '白色', '黑色']
  }
};

const FORM_RULES = {
  'zhu-long': {
    bodyPlan: '人首蛇身',
    aliases: ['人面蛇身'],  // 同义词也认可
    forbidden: ['西方龙', '蜥蜴', '四足龙']
  }
};
```

**拦截与自动修复：**
```
输入Prompt: "蓝色烛龙翱翔于永夜裂谷，展开西方龙的双翼"
              ↓
一致性检查:
  ❌ [color] "蓝色"在禁用列表 → 修复为"赤红"
  ❌ [form] "西方龙"在禁用列表 → 删除
  ⚠️ [form] 未检测到"人首蛇身" → 建议添加
              ↓
修正后: "赤红烛龙横亘于永夜裂谷，人面蛇身..."
```

##### 引擎3: Nirath世界观校准器 (nirath-world-sync.js)

**功能**: 确保神兽场景100%符合Nirath星球设定

**校准维度：**

```
1. 科技禁令（绝对红线）
   ❌ 机甲、飞船、激光、枪支、汽车、手机、电脑...
   ✅ 生物发光、能量晶体、原始工具

2. 栖息地生态匹配
   烛龙只能在"永夜裂谷" → 岩浆/黑暗/地核辐射
   应龙只能在"云雷高原" → 雷暴/万米高原/导电植被
   凤凰只能在"丹穴山脉" → 火山/金玉/金色尘埃

3. 能量体系统一
   必须用Nirath特有描述:
   ✅ "双恒星橙紫光芒交织"
   ✅ "地核辐射照亮"
   ✅ "生物电磁场共鸣"
   ❌ "阳光普照"（Nirath没有太阳，只有双恒星）

4. 时间线约束
   当前时间: 2150年殖民初期
   ❌ "工业化城市"
   ❌ "互联网"
   ❌ "核战争"
```

**校准示例：**
```
输入: "烛龙驾驶机甲飞船，使用激光武器"
        ↓
科技检查: ❌ 检测到"机甲""飞船""激光" → 全部删除
        ↓
输出: "烛龙横亘于永夜裂谷深处"
```

##### 引擎4: 运镜推荐器 (beast-camera-advisor.js)

**功能**: 根据神兽特性自动推荐最佳运镜方案

**映射逻辑：**
```
神兽体型 → 景别选择
神兽类型 → 运镜风格
神兽能力 → 特效运镜
神兽情绪 → 速度曲线
```

**体型→景别映射：**
| 体型等级 | 景别 | 原因 |
|----------|------|------|
| 超巨型(千里) | extreme_wide | 必须展示完整尺度 |
| 巨型(百米) | wide | 展示大部分身体 |
| 大型(数丈) | medium | 标准全身展示 |
| 中型(如人) | medium_close_up | 强调互动 |
| 小型(如猫) | close_up | 特写可爱细节 |

**神兽类型→运镜风格：**
| 类型 | 神兽 | 默认运镜 | 参考电影 |
|------|------|----------|----------|
| 超巨型 | 烛龙、鲲鹏 | extreme_wide + slow_push | 《降临》巨物美学 |
| 巨型 | 应龙、相柳 | wide + slow_push | 《哥斯拉》巨兽压迫 |
| 飞行 | 凤凰、朱雀 | wide + aerial_track | 《阿凡达》飞行场景 |
| 灵巧 | 九尾狐、英招 | medium + smooth_follow | 《神奇动物》灵动美学 |
| 凶兽 | 饕餮、穷奇 | close_up + sudden_shake | 《异形》紧张氛围 |
| 守护 | 麒麟、白泽 | wide + smooth_orbit | 《纳尼亚》阿斯兰 |

**场景类型调整：**
```
烛龙 + 展示 → extreme_wide + slow_push（全景震撼）
烛龙 + 战斗 → extreme_wide + fast_track（激烈对抗）
烛龙 + 对话 → medium + static（精神交流）
```

**人类同框特殊处理：**
```
小G + 烛龙 + 对视:
  人类位置: "前景下方，衬托神兽巨大"
  构图: "三分法，神兽占上2/3，人类占下1/3"
  交互: "中景缓慢推进，在人眼与兽眼间交替对焦"
```

## 三、完整链路演示：从MD到Prompt

### 输入：队长发送的MD档案（第二批神兽）

```markdown
## 【档案02】应龙

### ① 神兽名称
- **中文名称**：应龙
- **拼音注音**：Yìng Lóng
- **别名**：黄龙、庚辰

### ④ 神兽外观
有翼神龙，金黄色鳞甲遮天蔽日...翼展数百米的半透明彩虹翼膜...
```

### Step 1: MD解析器 (md-beast-parser.js)
```
输入: MD文本
  ↓
自动提取:
  - 名称: 应龙 / Yìng Lóng / 黄龙、庚辰
  - 级别: 创世神祇 / 战神至尊
  - 栖息地: 云雷高原
  - 外观: 有翼神龙、金黄鳞甲、翼展数百米
  - 颜色: 金黄、青铜、彩虹
  - 体型: 巨型
  - 身体结构: 有翼神龙
  输出: ying-long.json
```

### Step 2: 自动补全 (Enricher)
```
基于解析结果自动补充:
  - promptFragments.head: "龙头硕大修长前额突起"
  - promptFragments.body: "身躯覆满金黄青铜色坚硬鳞甲"
```
